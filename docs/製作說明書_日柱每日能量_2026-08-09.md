## 三、核心機制點運作

### 3.1 資料流

出生年月日 → `bazi-calc` 取日柱 → localStorage 只存日柱兩個字 → 每次開頁取今日流日干支（`bazi-daily`）→ `daily-relate(user, today)` → 查 `daily-copy` → 出卡。

⚠️ **私隱決定**：只存日柱，唔存生日原值。日柱係六十分之一嘅粗粒度，唔構成識別；生日係個人資料。UI 要明講呢一點，佢係信任資產唔係細節。

### 3.2 關係判定（daily-relate.ts）

輸出三格：

1. **天干十神**：流日天干對用戶日干，十種
2. **地支關係**：流日地支對用戶日支，八種（六合、半合、沖、刑、穿害、破、伏吟、無關）
3. **日柱標記**：用戶日柱是否屬日貴（丁酉丁亥癸巳癸卯）、日德（甲寅丙辰戊辰庚辰壬戌）、日刃（丙午戊午壬子）、魁罡（壬辰庚戌庚辰戊戌）、八專

主鍵 ＝ `${十神}_${地支關係}`，10 × 8 ＝ 80 格。日柱標記做修飾層，出多一句，唔參與主鍵。

⚠️ **更正（2026-08-11 實作時發現）：80 格入面只有 45 格出得街，其餘 35 格永遠行唔到。**

原因係六十甲子嘅結構：干支必定陰陽同性，所以天干嘅陰陽關係鎖死咗地支嘅陰陽關係。

- 同性十神（比肩、食神、偏財、七殺、偏印）＝兩個天干同陰陽 → 兩個地支亦必定同陰陽 → 只可能出 沖、半合、伏吟、無關
- 異性十神（劫財、傷官、正財、正官、正印）＝兩個天干異陰陽 → 兩個地支亦必定異陰陽 → 只可能出 六合、刑、穿害、破、無關

（六合六組、刑四組、穿害五組、破三組，兩支全部異陰陽；沖六組、半合十二組、伏吟十二組，兩支全部同陰陽。）

5 × 4 ＋ 5 × 5 ＝ 45。已喺 `tests/daily-spec.mjs` 釘死，`daily-copy.ts` 每個十神區塊註解都標咗邊幾格係活嘅。**Mic 審稿只需要審 45 格。**

另外，地支關係嘅重疊要仲裁：巳申同時係六合、刑、破；寅亥同時係六合、破；寅申同時係沖、刑；戌未同時係刑、破；辰辰等自刑同時係伏吟。實作採用嘅優先序係 **沖 ＞ 伏吟 ＞ 六合 ＞ 半合 ＞ 刑 ＞ 穿害 ＞ 破**（理據寫喺 `daily-relate.ts` 嘅 `PRIORITY` 註解）。呢個優先序**唔喺原本規格入面，係實作時補嘅決定**，要 Mic 拍板。改咗佢，可達嘅 45 格會變。

半合亦採取咗一個簡化：三合局入面任何兩支都當半合，冇再細分「有旺支」同「拱合（無旺支）」，因為 §3.2 訂死八種關係，加多一種就變九種。

### 3.3 文案庫規格

- 每格三段：一句定性、宜（兩件具體事）、不宜（一件具體事）
- ~~總量約 245 段（80 格 × 3 ＋ 5 段日柱標記）~~ → **實際要審 140 段（45 格 × 3 ＋ 5 段日柱標記）**，因為 80 格入面 35 格不可達，見 3.2 更正
- 語言：繁體書面語、全形標點、內文不用粗體、禁破折號
- 禁出街詞：流派名、十神術語。十神只做內部鍵，UI 唔准出現「今日七殺」呢類
- 寫法：先寫 80 格定性句，宜忌第二輪補。唔准一次過生成 245 段唔逐段審就上線

### 3.4 同首頁每日能量對接

首頁 hero 已有今日天干、地支、energyTitle。`/daily` 必須用同一個 source of truth（`bazi-daily.ts`），唔准各自計。

⚠️ **字型陷阱**：首頁每日變動嘅 serif 字已經收入 `scripts/build_font_subset.py` 嘅 `collect_dynamic()`。`/daily` 若用 `font-serif` 出新嘅每日變動文案，**必須同步加入 `collect_dynamic()` 再重跑 subset script**。2026-08-08 已經因為呢個位冧過一次，PSI 由 90 跌返 72。

## 六、命理規格（唔准自行更改）

本節全部經查庫（2026-08-09）。改動要重新查庫加 Mic 拍板。

**6.1 定位鐵律**：呢個功能係「日級引動提示」，唔係論命。所有對外文案跟呢個定位。

**6.2 可以做同唔可以做**

| 可以 | 唔可以 |
|---|---|
| 今日流日對用戶日柱嘅關係 | 性格判斷、「你係咩人」類斷語 |
| 由該關係推出嘅宜與不宜 | 富貴層次、財運高低 |
| 日柱本身特性（日貴日德日刃魁罡八專）一句修飾 | 姻緣、健康斷症、生死 |

原文根據：「不能單以一柱論命」「提綱為重」；單柱斷語生搬硬套「十有九差」；解像度上限係大致性格傾向或局部特徵，斷唔到富貴層次。

**6.3 層級鐵律**：流日喺大運、流年、流月、流日鏈嘅最末端，「力量在於引動而非決定」。UI 唔准出現「今日必定」「今年運勢」呢類翻大層級嘅講法。

**6.4 體系聲明**：本功能用八字五行生剋，唔係黃曆建除。典籍立場係五行為根本，建除十二神同二十八宿係「枝葉」，衝突以五行家為準。呢句可以直接做產品差異化文案。

**6.5 免責兼升級路徑**：UI 要明講「日柱只答得到今日，要答一世要四柱同時辰」。呢句唔係免責話術，係結構事實，亦係最自然嘅升級入口。

**6.6 無時辰之限制**：典籍立場「寧缺不濫」，「寧可進行六字的推算，也不要亂猜時辰來補綴」。故唔准用猜時辰去補足任何功能。

## 九、點解唔用 AI API

1. 判斷邏輯係確定性查表，冇生成成分。真變數得 80 格加 5 個修飾，寫死就完
2. 一致性係命脈。同一日同一日柱必須永遠出同一答案，用戶會互相比對
3. 免費 App 加每用戶每日一次 API call ＝ 邊際成本跟用戶升而收入唔跟。script 係零邊際成本
4. 最重要：runtime 用 LLM，個產品嘅判斷就唔係 Mic 嘅，係模型嘅。護城河就係嗰套判準被寫成 code
